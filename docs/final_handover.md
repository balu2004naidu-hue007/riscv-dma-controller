# RISC-V DMA project — final handover

## Project status

**Simulation-verified prototype.** The project owner ran the complete `make test-system-clang` acceptance target in Windows/MSYS2 UCRT64 on 2026-11-09. The Python reference tests, extended DMA RTL testbench, arbiter testbench, Clang RV32 firmware build and PicoRV32 + DMA integration simulation all completed successfully.

This is a simulation-verified educational prototype, not an FPGA implementation, silicon validation, formal proof or production-qualified DMA IP.

## What is included

- Single-channel, 32-bit, word-aligned memory-to-memory DMA controller in SystemVerilog.
- Descriptor validation and bounded descriptor chaining.
- CPU/DMA single-outstanding round-robin bus arbiter.
- Simulation SRAM and system fabric.
- PicoRV32 wrapper (the upstream core is fetched separately).
- Bare-metal C driver, example firmware, startup and linker files.
- Python reference model and 26 unit tests.
- DMA, arbiter and CPU-integration SystemVerilog testbenches.
- Architecture, register map, verification, setup and limitation documentation.
- Prebuilt RV32 firmware artifacts and waveform-review screenshot evidence.

## Reproducing the verified run

Use MSYS2 UCRT64 (or another compatible environment) with Python, GNU Make, Icarus Verilog/VVP, Clang/LLD, LLVM objcopy, Git and GTKWave.

From the project root:

```sh
python -m unittest discover -s tests -v
make test-rtl
make test-arbiter
bash scripts/get_picorv32.sh
make test-cpu-clang
make test-system-clang
```

The upstream PicoRV32 checkout used for the reported integration run was:

`ef203c2b0a3fb793280f5114941416c425c5b461`

The fetch script obtains the upstream repository. If reproducing the exact checkout, check out that commit after fetching:

```sh
git -C third_party/picorv32 checkout ef203c2b0a3fb793280f5114941416c425c5b461
```

Open waveforms generated by the simulations:

```sh
gtkwave build/dma_extended.vcd
gtkwave build/picorv32_dma.vcd
```

## Resume wording

Designed and simulation-verified a single-channel RISC-V DMA subsystem in SystemVerilog, integrating a PicoRV32 processor, bare-metal C driver, descriptor validation, bounded descriptor chaining, shared-bus round-robin arbitration, SRAM-range enforcement, interrupt/error reporting and abort/recovery. Validated with 26 Python unit tests, eight DMA RTL scenarios, arbiter simulation and CPU-driven DMA integration; benchmarked 16-, 64- and 256-byte transfers in simulation.

When discussing results, specify that the benchmark values are simulator cycles and that no FPGA or physical hardware measurement was performed.

## Design limitations

- This is a simulation/learning prototype, not an FPGA or silicon implementation.
- DMA access is restricted to `0x00001000..0x00007fff`; this is not a full IOMMU or system-wide memory protection unit.
- The simulation fabric uses a single writable SRAM model for the low memory window; it does not implement a physically read-only boot ROM.
- Transfers are 32-bit word-aligned, memory-to-memory, single channel, with one outstanding transaction.
- Abort is transaction-boundary controlled, not rollback. A write already outstanding may commit.
- Descriptor chains are not atomic; earlier completed descriptors remain complete if a later descriptor fails.
- CPU-copy and DMA benchmark windows differ: CPU copy loop versus DMA setup + transfer + polling. Simulator cycles are not physical throughput.
- No synthesis, timing closure, formal verification, FPGA board test or silicon test is claimed.
